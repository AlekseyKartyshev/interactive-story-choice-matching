# interactive-story-choice-matching
Интерактивная история со свободным вводом: модель семантического сходства сопоставляет ответ игрока с авторскими вариантами выбора, а LLM адаптирует текст до следующей точки выбора. Курсовая работа, программа двойного диплома СмолГУ и НИУ ВШЭ.

Рабочий датасет — русский перевод **The Intercept**: 128 карточек выбора, 350 вхождений авторских вариантов и 4 финала.
Добавлены **2 134 размеченных свободных ввода**: 1 750 с авторским вариантом и 384 без соответствия (`null`).
Основные файлы: [карточки с вводами](data/story_cards.json), [таблица вводов](data/user_inputs.csv), [описание полей и ограничений](data/README.md).

# Постановка задачи: сопоставление свободного ответа игрока с вариантами в интерактивной истории

| Вопрос (в скобках — пример для оттока абонентов) | Ваш ответ |
|---|---|
| **1. Бизнес-задача** | |
| Что улучшаем? *(меньше клиентов уходит к конкурентам)* | Даём игроку свободу писать свой ответ вместо выбора из списка, чтобы история ощущалась живой, а игрок реже бросал её из-за «не того» варианта. |
| Что сделают с прогнозом? *(звонок со скидкой, 1000 звонков в месяц)* | По предсказанному варианту движок продвигает сюжет по нужной ветке; если ответ не подошёл ни к одному варианту — показывает сцену-заглушку. Затем LLM слегка переписывает следующий кусок сюжета под формулировку игрока. |
| **2. ML-задача** | |
| Для чего и когда прогноз? *(абонент, 1-го числа на 30 дней)* | Для каждого ответа игрока в точке выбора, в реальном времени (сразу после ввода, задержка ≤ 1–2 с). |
| Таргет: как посчитать из данных? *(расторг договор или не платил 30 дней)* | Номер варианта, которому по смыслу соответствует ответ игрока, или метка «не подходит» (заглушка); размечают автор истории или разметчики. |
| Тип задачи *(бинарная классификация)* | Многоклассовая классификация с отказом (open-set): число вариантов меняется от сцены к сцене, поэтому решаем как сопоставление пары «ответ — вариант» (semantic matching) с порогом уверенности. |
| **3. Данные и признаки** | |
| Откуда данные, сколько их? Нет — где взять? *(биллинг и CRM за 2 года)* | Авторский сюжет [The Intercept](https://github.com/inkle/the-intercept/blob/master/Assets/Ink/TheIntercept.ink), его русский перевод в проекте и добавленная разметка свободного ввода: 2 134 примера для 128 карточек выбора. Из них 1 750 соответствуют авторским вариантам, 384 — ни одному. Формат и ограничения описаны в `data/README.md`. |
| Признаки на момент прогноза *(тариф, стаж, платежи, обращения до 1-го числа)* | Полный контекст текущей сцены, текст ввода игрока и варианты, доступные при текущем состоянии игры. |
| **4. Метрика и проверка** | |
| Метрика *(precision@1000 — сколько уходящих среди тех, кому позвоним)* | Macro-F1 по вариантам + отдельно precision сопоставления (не отправили по чужой ветке) и recall заглушки (поймали неподходящие ответы); главная ошибка — увести игрока в неверную ветку. |
| Бейзлайн без ML *(звоним всем с 3+ обращениями за месяц)* | Поиск ключевых слов / нечёткое совпадение строк с текстом варианта; если ничего не совпало — заглушка. |
| Как делим данные? *(по времени: обучаем на прошлых месяцах)* | Делим по исходным группам выбора (`source_group_id`), сохраняя повторные вхождения одного авторского варианта (`choice_id`) в одной части. Похожие вводы для одной сцены не должны попадать одновременно в обучение и тест. Примеры без полного контекста исключаем из оценки с контекстом; итоговую проверку проводим на новых вводах игроков. |
| **5. Результат (дома)** | |
| В каком виде результат? *(список из 1000 абонентов раз в месяц)* | Модуль/API: на вход — контекст сцены, варианты и ответ игрока; на выход — id варианта или «заглушка» с уверенностью, далее LLM адаптирует следующий фрагмент текста. |
| Как поймём, что работает? *(A/B-тест: ушло ли меньше среди тех, кому звонили)* | Плейтест / A/B: свободный ввод против обычного выбора — сравниваем долю дошедших до конца истории, долю «несправедливых» заглушек (по жалобам и ручной проверке выборки) и оценки игроков. |
