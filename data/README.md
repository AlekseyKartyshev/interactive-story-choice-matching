# Данные The Intercept для сопоставления свободного ввода

Основной файл — `story_cards.json`. В нём **132 карточки**: 128 моментов выбора и 4 сюжетных финала.
Сохранены 340 уникальных исходных вариантов ответа, 350 их вхождений в карточки и 670 маршрутов.
Повторные вхождения возникают из-за контекстов вызова подисторий; это не новые авторские ответы.

Добавлены **2 134 размеченных ввода**: по 5 на каждое из 350 вхождений авторских вариантов
и по 3 неподходящих на каждую из 128 карточек выбора. Из них **1 750** соответствуют варианту,
**384** имеют метку `null`. Тексты вводов и объяснений — на русском языке.

Авторский источник: [The Intercept — TheIntercept.ink](https://github.com/inkle/the-intercept/blob/master/Assets/Ink/TheIntercept.ink).
Данные используют имеющийся русский перевод истории. Свободные вводы находятся в `cards[].user_inputs`
внутри основного JSON и в отдельной таблице `user_inputs.csv`.

## Как устроена карточка

```json
{
  "id": "intercept_001",
  "kind": "decision",
  "story": "Меня заставляют ждать.",
  "choices": [
    {
      "id": "choice:78",
      "text": "Барак № 14",
      "conditions": [],
      "target_id": "intercept_002",
      "routes": [
        {
          "id": "intercept_route_0001",
          "target_id": "intercept_002",
          "conditions": [],
          "story": "Полный сюжет после ответа до следующего выбора…"
        }
      ]
    }
  ],
  "user_inputs": [
    {
      "id": "input_001_001",
      "text": "Я жду в четырнадцатом бараке.",
      "choice_id": "choice:78",
      "context_id": "intercept_entry_01",
      "rationale": "Продолжает сцену ожидания в бараке № 14."
    }
  ],
  "previous": [],
  "source": {"file": "TheIntercept.ink", "line": 77}
}
```

Пример показывает основные поля; в настоящем файле есть дополнительные сведения об источнике и покрытии.

| Поле | Смысл |
|---|---|
| `id` | Идентификатор карточки, на который ссылаются переходы |
| `story` | Полный текст при единственном контексте входа; общий суффикс при нескольких |
| `story_mode` | `single_context`, `shared_suffix` или `no_incoming_context` |
| `choices[].id` | Исходный вариант ответа; уникален в пределах карточки |
| `choices[].text` | Текст варианта, видимый игроку |
| `choices[].target_id` | Единственное назначение; `null`, если назначений несколько |
| `choices[].routes` | Все условные пути после этого ответа |
| `routes[].story` | **Сюжет от предыдущего выбора до следующей карточки**, включая её вводный текст |
| `routes[].conditions` | Условия маршрута; они сохранены, но не исполнялись |
| `previous` | Входящие ссылки: карточка, ответ и `route_id`, которые привели сюда |
| `source` | Привязка к строке Ink и исходной группе выбора |
| `reachable_from_start` | Наличие структурного пути от начала без проверки состояния игры |
| `user_inputs` | Размеченные свободные вводы для этой карточки; у финалов пустой список |
| `user_inputs[].id` | Уникальный ID примера во всём датасете |
| `user_inputs[].text` | Текст, который игрок мог бы ввести в этой сцене |
| `user_inputs[].choice_id` | ID авторского варианта этой карточки либо `null`, если соответствия нет |
| `user_inputs[].context_id` | Ссылка на полный входящий контекст из `contexts.csv`; исключение описано ниже |
| `user_inputs[].rationale` | Короткое обоснование правильной метки для проверки разметки |

**Почему story иногда пуст:** несколько веток входят в один момент выбора, но у их текстов нет общего суффикса.
Не заменяйте такие записи выдуманным текстом. Для EDA и последующей разметки используйте полный контекст из `contexts.csv`.

## Как читать разметку ввода

Каждая запись — отдельный пример, а не очередная реплика одного прохождения. В карточке с двумя
вариантами находятся 10 подходящих вводов (5 + 5) и 3 неподходящих, всего 13.
У семи карточек всего один авторский вариант; они также покрыты примерами, включая переходы вроде «Дверь открывается».

Метка определяется намерением в текущей сцене. Учитываются перефразирование, разговорная речь,
отрицания и уточнения. Если игрок намерен соврать, но препарат в чае заставляет героя говорить правду,
выбирается вариант попытки солгать: это действие игрока до сюжетного результата.
Неподходящие вводы включают посторонние вопросы, невозможные действия и понятные действия,
которых нет среди вариантов текущей карточки. Любая посторонняя фраза не становится автоматически вариантом «Уклониться».

В ряде сцен «Нет» и «Солгать» приводят к одинаковой реплике, а «Да» и «Сказать правду» — к одной ветви.
Вводы явно выражают соответствующий способ ответа. Такие авторские варианты не объединены:
для оценки перехода по сюжету учитывайте также совпадение ветвей, а не только буквальное равенство ID.

В `user_inputs.csv` сохранены `input_id`, `card_id`, `context_id`, `context_story`, `context_conditions`,
`text`, `choice_id`, `choice_text`, `choice_conditions`, `rationale`, `source_group_id`.
`choice_id` и `choice_text` для неподходящего ввода — пустые ячейки CSV; в JSON это `null`.
`context_story` содержит текст **до** текущего выбора, а не последствие размеченного ответа.
Все варианты-кандидаты берутся из `choices.csv` по `card_id` или из `cards[].choices` в JSON.

На вход модели подавайте контекст, текст игрока и доступные авторские варианты.
`choice_id`, `choice_text` выбранного ответа, `choice_conditions` выбранного ответа и `rationale`
служат разметкой и не должны попадать в признаки как сведения об уже выбранной метке.
Условия всех вариантов-кандидатов можно использовать для определения их доступности по состоянию игры.
После сопоставления переход выполняется по `choices[].routes` с учётом состояния, а не по номеру строки примера.
Для `null` авторская ветвь не выбрана: приложение должно попросить переформулировать ввод или обработать отказ.

## Ограничения

Это одна авторская история; примеры свободного ввода добавлены к ней отдельно от авторского сюжета.
Состояние переменных, счётчики посещений и `once_only` не вычислялись. Текст ⟨… / …⟩ сохраняет альтернативные формулировки.
Несколько маршрутов могут иметь одну и ту же карточку назначения и разные тексты входа.

Для каждого варианта выбран подходящий входящий контекст; это не отдельная разметка всех 671 контекстов
и не набор проверенных игровых прохождений. При запуске игры сначала отфильтруйте варианты по её состоянию:
варианты с условиями `drugged` и `not drugged`, например, не предлагаются одновременно.
Проверка исключает прямые логические противоречия выбранного входящего маршрута, но не заменяет исполнение Ink.

У `intercept_127` нет входящих маршрутов и текста сцены в исходном графе. Её 13 примеров сохранены
с `context_id: null` и пустым `context_story`; их следует исключать из оценки, требующей полного контекста.
Сюжет ради заполнения этих полей не дописывался.

Тексты не повторяются внутри карточек или между разными исходными вариантами.
50 повторных вхождений текста относятся только к повторным появлениям одних и тех же исходных вариантов;
всего уникальных формулировок **2 084**. При делении train/test держите исходные группы выбора
(`source_group_id`) и повторные вхождения одного `choice_id` в одной части выборки.
Объяснения меток также не используются как обучающие тексты игрока.

Проверки подготовки подтверждают покрытие всех **644 сюжетных строк** и **340 исходных вариантов** из полного графа.
Оригиналы и предыдущие визуализации перемещены в `previous_work/`; эта папка исключена из Git.

## Запуск

Из корня проекта:

```powershell
pip install -r requirements-eda.txt
```

Открыть `notebooks/story_eda.ipynb` и выполнить Run All. Notebook использует только JSON и код подготовки; архив для EDA не нужен.
Графики, признаки и итоговые выводы записываются в `eda/`.

EDA включает структуру истории и отдельные разделы по свободным вводам: проверку меток и контекстов,
баланс `choice_id`/`null`, покрытие каждого варианта, длины и формулировки текстов, повторы,
риск утечки между train/test, покрытие контекстов и лексическое сходство с кандидатами своей карточки.
Ноутбук читает вводы из JSON и проверяет их соответствие `user_inputs.csv`.

Основные результаты анализа вводов:

| Файл в `eda/` | Содержимое |
|---|---|
| `summary.md`, `summary.json` | Выводы и рассчитанные показатели истории и вводов |
| `user_input_features.csv` | Вводы, метки, контексты, длины, лексические признаки и диагностические группы разбиения |
| `input_quality_checks.csv` | Проверки целостности и покрытия разметки |
| `input_choice_coverage.csv`, `input_card_coverage.csv` | Число примеров для каждого варианта и карточки |
| `input_label_balance.csv`, `input_text_summary.csv` | Баланс меток и свойства текстов |
| `input_duplicate_groups.csv` | Повторяющиеся нормализованные вводы с исходными вариантами |
| `input_split_audit.csv` | Сравнение пересечений в диагностических разбиениях по строкам и связанным группам |
| `input_context_coverage.csv` | Покрытие входящих контекстов примерами |
| `input_choice_scores.csv` | Лексическое сходство пар «ввод — кандидат своей карточки» |
| `figures/08_*.png` — `figures/12_*.png` | Пять новых графиков по вводам; исходные семь графиков истории также сохранены |

Лексическое сходство в EDA не является оценкой семантической модели; порог отказа не подбирается.
Диагностические разбиения нужны для демонстрации риска утечки и не сохраняются как готовые train/test.
Аналитическая таблица `user_input_features.csv` содержит метки и результаты сравнения с ними:
перед обучением отбирайте только допустимые входные признаки, не включая ответ или его объяснение.

Повторная подготовка из локального архивного графа:

```powershell
python scripts/prepare_story_data.py
```

Повторное построение в существующий `story_cards.json` сохраняет разметку ввода и обновляет её CSV.
Для добавления примеров к заново подготовленному JSON или повторного экспорта:

```powershell
python scripts/add_user_inputs.py
```

Проверка количества, меток, ссылок на контекст, уникальности и покрытия без изменения данных:

```powershell
python scripts/add_user_inputs.py --check-only
```

Сценарии подготовки находятся в локальной папке `scripts/`, исключённой из Git.
JSON и CSV уже содержат полную разметку и пригодны для чтения без этих сценариев.

После нового построения notebook можно выполнить без Jupyter-интерфейса:

```powershell
python scripts/build_eda_notebook.py
python scripts/run_eda_notebook.py
```
